|---|---|
| high-rep extrapolation is not fixed | 🔄 **THE LADDER HALF IS FIXED AND MEASURED AS OF 2026-09-20 — see the end of this row; the rest of the problem is still open, because nothing in the app knows whether a set was taken to failure (D28) and that is the largest single source of error in the whole model.** Before that it read *partly* — the rating prefers sets at ≤ 8 reps where they exist, so the longest set no longer leads by default. 🔄 **AND SINCE 2026-09-20 THAT PREFERENCE CAN NO LONGER PUNISH YOU FOR DOING MORE.** It was a filter, not a weighting, and `seatCredit` contains no weight term at all — so a set heavier AND longer than the seated one could not win the seat, only lose it. Tim caught it on his own Back: a Lat Pulldown 50×6 held the seat while an 85×12 three weeks newer contributed **0.00 lb**, and the discarded set implied 131 against the seated 66.7. **A set that is ≥ in BOTH weight and reps now supersedes**, re-read at the weaker set's rep count — heavier at the same credibility, and the conservative half of what it proves. Heavier-but-shorter is untouched: that is a real trade and the credibility comparison still decides it. `dominate()` in muscle-evidence.js. 🚨 **IT IS CALLED TWICE AND BOTH ARE REQUIRED** — once on each exercise-DAY before `betterSameDay` collapses it, and once at the seat. Shipping it at the seat alone left the reporter's own case broken and looked green in every suite: on the day he pulled 85×12 he had opened with 65×8, and the per-day collapse uses the *same* weight-blind comparison, so the heavy set died one step early. **A rule enforced at one of two places that make the same comparison is not enforced.** ⚠️ **The demo year never produces that shape**, so the golden table did not move when the second half went in — there was no cover until a fixture was written for it, and the check not done was driving the change against the reporter's own described case (*"my third set"*) rather than a simplification of it. 🛑 **IT MUST RUN NO EARLIER THAN THE DAY COLLAPSE** — three attempts in `buildObservations()` collapsed repeat sets, folded a progressive year onto a handful of dates (720 observations → 44), and **disabled the typo quarantine** (a mistyped 2050×5 dominates everything, drags every real set up to its weight, and leaves the day-screen nothing to disagree with — Chest read Elite at 2282 lb). A rule that rewrites evidence runs after everything that screens it. 🚨 **AND THE SAME DAY THE DISCOUNT ITSELF STOPPED BEING A GUESS.** Tim asked the question nobody had — *"I don't know where the 45% trust is coming from… I want higher-rep counts to count towards the 1RM estimation almost the same as lower-rep counts, unless there is a good amount of data that agrees with each other recorded for that 1RM already, so using the low rep count just adds precision and confidence"* — and the answer was **nowhere**. `repFactor()`'s 1.00 / 0.95 / 0.85 / 0.70 / 0.45 / 0.25 was hand-typed, no tool fitted it, `docs/research.md` does not contain it, and its own comment cited the research only for the SHAPE. It was also a staircase: eleven reps worth 36 % less than ten, thirteen 44 % less than twelve, flats between, on literature that says *degrades above ten* rather than *worth half*. **σ_rep is what replaced it** — `js/rep-sigma.js`, GENERATED by `tools/build-rep-sigma.mjs`, measuring how far the seven classical formulas of research §1.2 DISAGREE about the r → 1 extrapolation, each normalised by its own f(1) first so a single (which converts nothing) comes out at exactly 0. **0 % at 1 rep, 2.6 % at 6, 3.1 % at 8, 4.2 % at 10, 5.9 % at 12, 9.6 % at 15**: smooth, monotone, and the same technique `tools/build-ratio-sigma.mjs` already applied to the conversion ratios, so the second input that was carrying a judgement now comes from seven independent authors instead of this project. ⚠️ **IT LIVES IN `readingSigma()`, WHICH IS A SECOND FUNCTION RATHER THAN A BIGGER `sigmaFor()`, AND A FAILING TEST IS WHAT INSISTED**: `sigmaFor()` is documented and asserted as the CONVERSION doubt — *"a key lift carries none of it, its ratio is 1.00 by construction"* — and folding the rep term in made that sentence false while every caller still read it as true. Two doubts, two functions, combined **in quadrature**, and the caller says which it wants. 🚨 **THE QUADRATURE IS WHAT DELIVERS HIS ASK WITH NO SPECIAL CASE, AND IT IS MEASURED**: on a machine, where the conversion is already doubtful, a 12-rep set carries **86 %** of an 8-rep set's weight — *"almost the same"*, because the rep count is not what the doubt is about; on the key lift, where the ratio is exact and σ_rep is nearly all that is left, **57 %**, so low reps genuinely *"just add precision"*. The ladder said **53 % in both cases**. One extra rep now costs at most **21 %** of a set's weight against the ladder's **44 %**. ⚠️ **The key lift's 57 % against the ladder's 53 % is close, and that is the honest result rather than a failure** — where the rep count IS most of the doubt a measured σ and a hand-drawn ladder happen to agree; the ladder's fault was never that every number was wrong, it was that it gave the SAME answer everywhere. 🛑 **`repFactor` SURVIVES ONLY AS THE SEAT COMPARISON.** It is out of the blend weight (`evidenceWeight / quality / repFactor(reps)` divides it back out) because charging a long set once as a multiplier and again as a variance is the same doubt twice — but it still decides which of an exercise's own sets speaks, which is a different question from what that set's number is worth. Recency, fatigue and the benchmark bonus stay in the blend: none of them is a statement about how far the curve is extrapolating.
